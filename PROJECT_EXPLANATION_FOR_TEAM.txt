AI Resume Generator & ATS Optimizer — Team Explanation Guide
================================================================

Think of this as: "How to explain our project to a 10-year-old (who happens to be a developer)"


WHAT IS THIS PROJECT? (The Elevator Pitch)
==========================================

In one sentence: We built a FREE, NO-LOGIN website where anyone can create a professional resume, paste a job description, get an AI-powered "ATS score" telling them how well their resume matches that job, have AI rewrite their bullet points to sound more professional, and download a beautiful PDF or Word document — all without ever creating an account.

The problem we solve: Most job seekers suck at writing resumes. They either:
- Don't know what to write (blank page syndrome)
- Write vague bullets like "Responsible for managing projects" instead of "Led 5-person team delivering $2M project 2 weeks early"
- Don't know if their resume will pass the robot (ATS) that filters applications before humans see them
- Don't tailor their resume to each job (because it's too much work)

Our solution: One tool that does ALL of it — build → analyze → optimize → export.

API ROUTES & ENDPOINTS (The Contract)
=====================================

All endpoints live under /api/v1/. Every request/response is JSON except exports (binary files).

| Method | Endpoint                  | What It Does                                      | Request                                    | Response                              |
|--------|---------------------------|---------------------------------------------------|--------------------------------------------|---------------------------------------|
| POST   | /resume/parse             | Upload PDF/DOCX to get structured resume         | multipart/form-data (file)                 | ParsedResumeResult (resume + confidence per section) |
| POST   | /resume/validate          | Check if resume is export-ready                  | { resume: Resume }                         | { is_export_ready, missing_fields[] } |
| POST   | /job-description/analyze  | Extract skills/keywords from JD                  | { input: JobDescriptionInput } or file     | JobDescriptionAnalysis (required/preferred skills, keywords) |
| POST   | /ai/generate              | Rewrite summary/bullets/achievements             | { request: AIGenerationRequest }           | AIGenerationResult (generated text + guardrail status) |
| POST   | /analysis/score           | Compare resume vs JD to get ATS score            | { resume, job_description_analysis }       | ATSScoreResult (score, sub-scores, keywords, recommendations) |
| POST   | /export/pdf               | Generate PDF from resume + template              | { resume, template_id }                    | Binary PDF stream (download)          |
| POST   | /export/docx              | Generate DOCX from resume + template             | { resume, template_id }                    | Binary DOCX stream (download)         |

ERROR FORMAT (always the same):
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": { "fields": ["email: invalid format"] }
  }
}

HTTP STATUS CODES:
- 200 = Success
- 400 = Bad request (missing data)
- 413 = File too big (>10MB)
- 415 = Wrong file type (not PDF/DOCX)
- 422 = Validation failed (bad data format)
- 429 = Rate limited (too many requests)
- 502 = AI service failed (Groq down)
- 504 = AI timeout (took too long)
- 500 = Server error (we messed up)

KEY COMPONENTS EXPLAINED SIMPLY
===============================

1. ZUSTAND STORES (4 of them)
------------------------------
Think of these as GLOBAL JAVASCRIPT VARIABLES that any component can read/write, and when they change, the UI auto-updates.

| Store                      | Holds                                    | Key Methods                                                              |
|----------------------------|------------------------------------------|--------------------------------------------------------------------------|
| useResumeStore             | Entire resume object + dirty flag        | addExperience(), updatePersonalDetails(), loadParsedResume()            |
| useJobDescriptionStore     | JD input + analysis result               | setInput(), setAnalysis(), reset()                                      |
| useAnalysisStore           | ATS score + staleness flag               | setScoreResult(), markStale(), reset()                                  |
| useTemplateStore           | Selected template ID + zoom              | setTemplate(), setZoom()                                                |

2. AISUGGESTIONPANEL (The Reusable AI Widget)
----------------------------------------------
One component used in 4 places: Summary, Experience bullets, Project bullets, Achievements.

FLOW:
User clicks "Rewrite with AI"
    ↓
Shows spinner: "Thinking..."
    ↓
Calls /api/v1/ai/generate with:
  - action_type: "rewrite_summary" | "rewrite_experience_bullets" | etc.
  - source_content: current text
  - job_description_analysis: (optional) for tailoring
    ↓
Backend returns generated text + guardrail_validated: true/false
    ↓
Panel shows: ORIGINAL vs AI SUGGESTION side by side
    ↓
User chooses: [Accept] [Edit] [Discard]
    ↓
If Accept: updates Zustand store → live preview updates instantly

3. TRUTHFULNESS GUARDRAIL (Our Secret Sauce)
---------------------------------------------
RULE: AI must NEVER invent facts. Only rephrase what user already wrote.

HOW IT WORKS:
1. System prompt: "You are a resume editor. NEVER add skills, employers, dates, numbers not in source."
2. User content wrapped in delimiters: --- BEGIN RESUME --- ... --- END RESUME ---
3. After AI generates, backend compares:
   - Original entities (company names, skills, dates, numbers)
   - Generated entities
4. If new entities appear → REJECT → retry with stricter prompt (max 2 retries)
5. If still fails → return error to user: "Couldn't generate safely, please edit manually"


SECURITY FEATURES (What We Did Right)
=====================================

| Threat                    | Our Defense                                                            |
|---------------------------|------------------------------------------------------------------------|
| Fake file uploads         | Check magic bytes (not extension), reject non-PDF/DOCX                |
| Huge files                | 10MB limit client + server                                            |
| Path traversal            | Random temp filenames (uuid.hex[:8]), never user filename             |
| Prompt injection          | Delimited boundaries, system prompt priority, post-generation validation|
| XSS                       | React auto-escapes everything, no dangerouslySetInnerHTML             |
| PDF XSS                   | HTML-escape all fields before ReportLab rendering                     |
| CORS                      | Allow-list only (BACKEND_CORS_ORIGINS), no wildcard                   |
| Secrets leakage           | GROQ_API_KEY backend-only, never NEXT_PUBLIC_                         |
| Sensitive logs            | Structured JSON logs, NO resume/JD content, only metadata             |
| Rate limiting             | Per hashed IP, 10 req/min on AI endpoints                             |
| Temp file cleanup         | Immediate + scheduled backstop (5 min max)                            |
| SQL injection             | No user data in DB, parameterized queries for rate limits only        |


DATA SCHEMA (The Shape of Everything)
=====================================

RESUME (Root Object)
--------------------
Resume
├── personal_details (REQUIRED)
│   ├── full_name (max 120) ← REQUIRED for export
│   ├── professional_title (max 150)
│   ├── email (valid format)
│   ├── phone (max 30)
│   ├── location (max 150)
│   └── links[] { label, url }
├── professional_summary (max 800 chars)
├── experience[] (ordered)
│   ├── id (UUID)
│   ├── company_name (max 150, required)
│   ├── job_title (max 150, required)
│   ├── start_date (required, YYYY-MM)
│   ├── end_date (required, YYYY-MM or "present")
│   ├── description_bullets[] (each max 400)
│   └── order_index
├── education[] (similar structure)
├── projects[] (similar structure)
├── skills[] (SkillGroup: category + skills[])
├── certifications[]
├── achievements[] (statement, max 300)
├── references (either array OR "available_upon_request")
└── meta { source: "created"|"uploaded", created_at, updated_at }

JOB DESCRIPTION ANALYSIS
------------------------
JobDescriptionAnalysis
├── required_skills[] (must-have)
├── preferred_skills[] (nice-to-have)
├── responsibilities[]
├── keywords[] { term, importance: "required"|"preferred", source_context }
└── analysis_confidence: "high"|"medium"|"low"

ATS SCORE RESULT
----------------
ATSScoreResult
├── overall_score (0-100)
├── sub_scores
│   ├── keyword_coverage (deterministic: % of JD keywords in resume)
│   ├── skills_alignment (AI judgment)
│   ├── experience_relevance (AI judgment)
│   └── formatting_compatibility (deterministic: sections complete, no tables)
├── matched_keywords[]
├── missing_required_keywords[]
├── missing_preferred_keywords[]
├── recommendations[] { priority, message, related_section }
├── computed_at (timestamp)
└── resume_snapshot_hash (detects if resume changed after scoring)

THINGS YOU MIGHT HAVE MISSED (But Should Know)
==============================================

1. NO DATABASE FOR USER DATA (BY DESIGN)
   We don't store resumes/JDs in Supabase. All data lives in BROWSER MEMORY (Zustand).
   User closes tab = data gone. This is a FEATURE for privacy/no-login.

2. TWO WAYS TO CREATE A RESUME
   - From scratch: User fills 9-section form manually
   - Upload + Parse: User uploads PDF/DOCX → AI structures it → user reviews/fixes → continues
   Both converge to the SAME builder interface.

3. AI ACTIONS ARE SECTION-SPECIFIC
   - Summary: "Generate" (empty) or "Rewrite" (has content)
   - Experience: "Rewrite bullets" per entry
   - Projects: "Rewrite bullets" per entry
   - Achievements: "Rephrase with measurable phrasing"
   Each calls /ai/generate with different action_type.

4. STALENESS TRACKING
   If user edits resume AFTER getting ATS score, useAnalysisStore marks score as STALE.
   UI shows "Score may be outdated — re-analyze" banner. Prevents false confidence.

5. EXPORT VALIDATION HAPPENS TWICE
   1. Client-side (instant): Checks name + at least one section
   2. Server-side (defensive): Backend re-validates before generating file

6. PROMPT TEMPLATES ARE VERSIONED FILES
   Not inline strings. In backend/app/prompts/:
   - resume_structuring_prompt.py — for parsing uploaded resumes
   - job_description_prompt.py — for JD analysis
   - generation_prompts.py — 5 templates for rewriting
   - scoring_prompt.py — for AI qualitative scoring
   Easy to A/B test, version, and audit.

7. DETERMINISTIC + HYBRID SCORING
   - Keyword coverage = pure math (count matches / total JD keywords) — reproducible
   - Formatting compatibility = pure math (sections present, no tables) — reproducible
   - Skills alignment = AI judgment — nuanced
   - Experience relevance = AI judgment — nuanced
   This makes scores EXPLAINABLE and PARTIALLY REPRODUCIBLE.

8. FILE NAMING CONVENTION
   Exports download as: {full_name}_Resume.pdf (sanitized). If no name: Resume.pdf.

9. ENVIRONMENT VARIABLES ARE SPLIT
   | Prefix          | Where       | Example                    |
   |-----------------|-------------|----------------------------|
   | GROQ_API_KEY    | Backend only| Secret, never in frontend  |
   | NEXT_PUBLIC_*   | Frontend    | Safe to bundle in JS       |
   | SUPABASE_*      | Both        | Different keys per env     |

10. CORRELATION IDs FOR DEBUGGING
    Every API request gets a X-Correlation-ID header. Logs include it.
    Trace a user's journey across parsing → analysis → scoring → export in logs.

==================================================

"Imagine you're applying for jobs. You have a resume, but you're not sure if it's good. You find a job you like. Our tool lets you:

HOW TO CONTRIBUTE / EXTEND
==========================

ADDING A NEW AI ACTION (e.g., "Rewrite Education"):
1. Add action_type enum in backend/app/models/analysis.py
2. Add prompt template in backend/app/prompts/generation_prompts.py
3. Handle in AIOrchestrationService.generate()
4. Add Zod schema in frontend/lib/schemas/analysis.ts
5. Use AISuggestionPanel in Education section with new actionType

ADDING A NEW TEMPLATE:
1. Add template ID in useTemplateStore default options
2. Create render logic in pdf_generator.py and docx_generator.py
3. Add preview component in template-preview feature
4. Update template selector UI

ADDING A NEW EXPORT FORMAT (e.g., HTML):
1. Add /export/html route in backend/app/api/v1/export.py
2. Add generator in backend/app/integrations/html_generator.py
3. Add export button in frontend Export modal
4. Call new API endpoint from useExport hook
